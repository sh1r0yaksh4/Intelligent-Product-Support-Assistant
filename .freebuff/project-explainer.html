Intelligent Product Support Assistant

A local-first, version-aware RAG system that gives hardware support answers grounded in verified documentation — and gracefully refuses to guess.

Gemini 3.6 Flash ChromaDB Vector Store Google Search Grounding Zero-Hallucination Guard Self-Improving Memory

01 Why This Exists

The core problem: wrong hardware instructions can brick devices.

⚠️ The Danger

Providing incorrect reset sequences, voltage ratings, or firmware versions for hardware like routers, headphones, and IoT devices can permanently damage or brick products.

🎯 The Approach

Strictly ground every answer in verified documentation (official manuals, support pages). If evidence is missing, escalate safely to the manufacturer instead of guessing.

🧠 The Memory

High-quality answers promoted through human feedback improve future responses without ever overwriting or contaminating the immutable official documentation.

03 Request Processing Pipeline

Step-by-step walkthrough of how a user question becomes a grounded answer.

1

Conversation Assessment

assess_conversation() in rag/gemini.py sends the latest message + history to Gemini as structured JSON. It decides: do we have enough product + issue context, or should we ask one short clarification question? Returns action: "clarify" or action: "answer" with extracted product name, manufacturer, model, and hardware version.

2

Standalone Query Formulation

ProductAssistant._standalone_query() in rag/chatbot.py concatenates the product name, hardware version, recent user turns, and the current question into a single retrieval-ready string. This decouples the vector search from conversational context.

3

Dual-Collection Vector Retrieval

Retriever in rag/retriever.py queries two ChromaDB collections simultaneously:

• product_documents — immutable official documentation chunks, filtered by product_id and optionally hardware_version using $and metadata filtering
• approved_interactions — user-validated historical Q&A pairs, filtered by product_id only

Both use gemini-embedding-001 (768-dim) with task type RETRIEVAL_QUERY. Scores are converted from ChromaDB cosine distance: score = max(0, 1 - distance).

4

Relevance Gate & Tier Selection

The best local chunk score is compared against MIN_DOCUMENT_SIMILARITY (default 0.42). This is the critical decision point:

Score ≥ threshold → Strict grounded generation with local evidence only (temperature 0.1, max 700 tokens)
Score < threshold → Google Search grounding fallback via Gemini's native web search tool

5

Zero-Hallucination Guard

The system prompt in SYSTEM_INSTRUCTIONS tells Gemini to respond with NOT_FOUND: if the evidence is insufficient or contradictory. Any NOT_FOUND: prefix — whether from local grounding or web search — triggers _escalation(), which returns a safe message directing the user to official manufacturer support.

6

Response Assembly & Citation

A ChatResult dataclass bundles the answer, up to 3 Citation objects (title, URL, section, source type), flags for escalated, used_search, used_memory, and clarification_needed. app.py renders citations as styled inline badges beneath the assistant message.

7

Interaction Logging & Feedback Loop

Every non-clarification response is recorded to data/interactions.jsonl via record_interaction(). When the user clicks "Helpful", submit_feedback() promotes the Q&A into the approved_interactions ChromaDB collection — creating a self-improving verified memory that is isolated from official documentation.

04 Component Breakdown

Every file in the system and its role.

UI Layer Orchestration AI / LLM Data / Storage Safety

🖥️ Streamlit Frontend

app.py

Dark charcoal GPT-minimalist chat UI. Manages session state, chat history persistence (chats.json), file upload popover, and auto-indexing. Renders messages, citations, and feedback buttons.

🧠 ProductAssistant

rag/chatbot.py

Central orchestrator. Coordinates the entire pipeline: assess → formulate query → retrieve → gate → generate or fallback → escalate. Constructs strict grounding prompts with system instructions.

🔮 Gemini API

rag/gemini.py

Unified wrapper for Gemini 3.6 Flash. Handles conversation assessment (JSON mode), product extraction (JSON mode), embeddings (768-dim), grounded generation, and Google Search grounding with 429 graceful handling.

🔎 Vector Retriever

rag/retriever.py

ChromaDB persistent client querying both document and memory collections. Supports $and metadata filtering for hardware version isolation. Cosine distance converted to similarity score.

📐 Document Indexer

rag/indexer.py

Manages ChromaDB collections with HNSW cosine index. Batch-embeds document chunks (40/batch) and stores with full metadata. Supports deletion and source-specific rebuilds.

📄 Document Loader

rag/loader.py

Parses PDFs (pypdf), Markdown, and TXT files into semantic chunks. 400-word chunks with 50-word overlap. Detects FAQ format (Q/A pairs). Falls back to OCR for scanned PDFs via pytesseract.

🌐 Source Manager

rag/sources.py

Handles file uploads (saves to data/products/{slug}/), web page fetching via requests + BeautifulSoup, and source URL mapping (.source_urls.json). Supports PDF and Markdown web content.

💬 Interactions

rag/interactions.py

JSONL audit trail for every Q&A exchange. submit_feedback() validates non-escalation + citations, then promotes to approved_interactions. Records helpful/not_helpful status.

🛡️ OCR Fallback

rag/ocr.py

Graceful OCR for scanned/image-only PDFs using pytesseract + pdf2image. Returns list of (page_number, text) tuples. Never crashes the application if OCR binaries are unavailable.

⚙️ Configuration

rag/config.py

All constants: model names, similarity thresholds, collection names, directory paths, embedding dimensions. Loads .env via python-dotenv. Provides slugify() utility.

📦 Data Models

rag/models.py

Dataclasses: ProductEntity, SourceMetadata, DocumentChunk, RetrievedChunk, Citation, ChatResult. Defines the type contracts for the entire pipeline.

📊 Evaluation

evaluation/

Golden Questions benchmark (golden_questions.csv) and CLI runner (run_eval.py). Asserts pass/fail on answer accuracy, citation presence, and escalation safety.

05 Three-Tier Evidence Retrieval

The system falls through increasingly broad evidence sources, never inventing information.

Tier Source When Used Example Result
Tier 1 — Local Docs ChromaDB product_documents Official manual PDFs, TXT, MD indexed for the product TP-Link Archer AX21 V1 manual, page 12 — reset procedure Answer with exact page/section citation
Tier 1b — Memory ChromaDB approved_interactions Prior user Q&A promoted via "Helpful" feedback Previous answer about same product's LED codes Supplements Tier 1 evidence
Tier 2 — Web Grounding Gemini Google Search Tool Local docs missing, insufficient similarity, or product unknown Official TP-Link support page for AX21 V2 firmware Answer with web citations from API annotations
Tier 3 — Escalation Manufacturer support link Neither tier produces verified evidence, OR response starts with NOT_FOUND "Please check TP-Link's official support portal" Safe escalation message + support URL

🛡️ Safety Invariant

If evidence is missing, contradictory, or hardware-version mismatched, the system escalates gracefully with a link to official support rather than inventing procedures, pinouts, or voltage ratings. This is the SYSTEM_INSTRUCTIONS contract enforced in every generation call.

Photo-based hardware identification

Anti-Poisoning

Memory validation before promotion

🛡️ Priority 1: Memory Poisoning Defense

Design multi-stage validation before promoting user chats to permanent memory: LLM judge, semantic consistency check against official docs, citation validity verification, and injection scanning.

👁️ Priority 2: Visual Troubleshooting

Enable photo uploads for LED patterns, damaged ports, model stickers. Auto-extract product info via OCR, diagnose error codes, match against diagram figures in manuals.

🤖 Priority 3: Agentic Router

Replace static conditional branching with ReAct-style tool-calling agent that dynamically decides between vector search, web fetch, image inspection, or clarification.

⚡ Priority 4: Token Streaming

Replace spinner-based waiting with st.write_stream + Gemini's generate_content_stream for real-time response rendering.
